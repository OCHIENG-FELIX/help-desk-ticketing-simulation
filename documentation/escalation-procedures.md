# IT Support Escalation Procedures

## Overview
Escalation is the process of transferring an IT issue to a higher support level or appropriate specialist when it cannot be resolved within the current technician's authority or expertise.

## Support Levels

### Level 1 (L1)
Handles common user issues and initial troubleshooting.

Examples:
- Password reset requests.
- Basic application issues.
- Printer connection checks.
- Basic connectivity troubleshooting.

### Level 2 (L2)
Handles more complex technical issues requiring deeper investigation.

Examples:
- Network configuration problems.
- Advanced operating system troubleshooting.
- Complex application failures.
- Driver and system configuration problems.

### Level 3 (L3)
Handles highly specialized issues, often involving infrastructure specialists, engineers, vendors, or developers.

Examples:
- Server infrastructure failures.
- Complex network architecture problems.
- Software defects requiring developer intervention.

## When to Escalate
- The issue exceeds the technician's permissions.
- Initial troubleshooting has not resolved the problem.
- The issue requires specialist knowledge.
- A critical service is affected.
- There is a security or data protection concern.

## Escalation Procedure

1. Record the issue and symptoms.
2. Document troubleshooting already performed.
3. Record relevant error messages and evidence.
4. Identify the appropriate support team.
5. Communicate the impact and urgency.
6. Transfer the ticket with complete notes.
7. Follow up according to support procedures.

## Important Considerations
- Do not attempt unauthorized configuration changes.
- Do not expose user credentials.
- Communicate clearly with the affected user.
- Maintain ticket ownership or follow-up responsibility according to organizational policy.

## Objective
Ensure issues reach the correct technical team without unnecessary delays or loss of information.
